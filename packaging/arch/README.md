# Arch Linux / AUR package

| File | Purpose |
|---|---|
| `PKGBUILD` | builds the `yt-downloader` package from the GitHub release tarball |
| `.SRCINFO` | metadata the AUR requires; regenerated by `aur-publish.sh` |
| `aur-publish.sh` | sets the checksum, test-builds, and pushes to the AUR |

The package uses Arch's own `pyside6`, `yt-dlp` (which pulls in Deno) and `ffmpeg`, so `pacman -Syu` keeps them updated.

## First-time setup (once)

1. **Create an SSH key** (the AUR only accepts pushes over SSH):
   ```bash
   ssh-keygen -t ed25519 -C "thevoidofficialprivacy@gmail.com" -f ~/.ssh/aur
   ```
   Then add this to `~/.ssh/config`:
   ```
   Host aur.archlinux.org
       IdentityFile ~/.ssh/aur
       User aur
   ```
2. **Create an AUR account** at <https://aur.archlinux.org/register>. Paste the contents of `~/.ssh/aur.pub` into the **SSH Public Key** field (you can also add it later under *My Account*).
3. **Install the tools:**
   ```bash
   sudo pacman -S --needed base-devel pacman-contrib namcap git
   ```

## Publishing a version

The AUR package downloads the source from GitHub, so the release has to exist **first**:

1. Push the repository to `github.com/MRVIMA/yt-downloader`, then tag the release:
   ```bash
   git tag v1.0.0 && git push origin v1.0.0
   ```
2. Do a dry run. It checks the tag, fills in the checksum, test-builds the package and runs `namcap`:
   ```bash
   bash packaging/arch/aur-publish.sh --dry-run
   ```
3. Publish:
   ```bash
   bash packaging/arch/aur-publish.sh
   ```
   The first push creates the package at <https://aur.archlinux.org/packages/yt-downloader>.
4. Commit the updated `PKGBUILD` and `.SRCINFO` back to this repo.

## Updating

Bump `pkgver` (and reset `pkgrel=1`) to match the new GitHub tag, then run `aur-publish.sh` again.
For packaging-only fixes on the same version, bump `pkgrel` instead.

## Rules worth knowing

- Never push a package whose source doesn't exist yet; users would get a download error.
- Answer comments on the AUR page. Inactive packages can be orphaned and taken over.
- The AUR is for source packages. To also offer the prebuilt AppImage, create a separate `yt-downloader-bin` package.
